# RCA — ai-personalos deploy failure

## Summary
Two distinct problems surfaced. The first (a `pull_source` hard-fail on a missing `frontend/.env`) was fixed by a manifest override and the pipeline advanced. The second failure — `yarn build` → `error Command "build" not found.` at `build_image` — is a **template/architecture mismatch** that is NOT manifest-fixable. The app is a Next.js 15 npm-workspaces monorepo deployed on the FARM template (`fastapi_react_mongo_shadcn_base_image`), which cannot build or run it.

## Timeline / Evidence

### Failure 1 — pull_source (FIXED by me)
Original run `c6916c7f-...` failed at `pull_source`:
```
prepare build context: read envs: read env file frontend/.env: open .../app/frontend/.env: no such file or directory
```
Cause: `config.yaml` `env_paths` listed `frontend/.env`, but this app has no `frontend/.env`. Fix applied: wrote a `config.yaml` manifest override (plus the complete farm manifest set) with `env_paths` reduced to just `backend/.env`. This was correct — the resumed run `8c6a5575-...` passed `pull_source`.

### Failure 2 — build_image (NEEDS E1 / architecture decision)
Resumed run `8c6a5575-...` failed at `build_image`:
```
#23 [frontend-build] Setting up frontend environment...
error Command "build" not found.   (yarn build, in /app from COPY frontend/)
#26 sed: /app/.env: No such file or directory
```
Inspected the source in an eph sandbox. The repo is a **monorepo with npm/yarn workspaces**, NOT a flat FARM app:

- Root `package.json`: `"workspaces": ["packages/*","apps/*"]`; real build is `"build": "npm run build --workspace @personalos/web"`.
- `frontend/package.json` is a **dev runner shim** — only script is `start` (proxies to `npm run dev --workspace @personalos/web`). **No `build` script** → the FARM Dockerfile's `COPY frontend/ /app/ && yarn build` fails.
- `apps/web/package.json` = `@personalos/web`, **Next.js ~15.5 (React 19)**: `build: next build`, `start: next start`. `next.config.ts` uses `rewrites()` to proxy `/api/*` and sets `outputFileTracingRoot`; **no `output: 'export'`** → this is an SSR server app, not a static bundle. The FARM/cloudflare path serves static files (nginx `try_files` / R2), which a Next.js SSR app does not produce.
- `apps/api/package.json` = `@personalos/api`, a **Fastify (Node/TypeScript, `tsx`) API** using **Postgres** (`pg`, `@electric-sql/pglite`, `drizzle-orm`) on port 8080.
- `backend/server.py` = FastAPI that acts as a **supervisor/proxy**: it `subprocess`-spawns the Node API and proxies to `http://127.0.0.1:8080`.

### Why this cannot run on FARM (even with a patched build)
1. FARM runtime image has **no Node runtime** (node/yarn exist only in the build/eph sandbox, not the deployed image) — `next start` and `tsx` (the Fastify API) cannot run in production.
2. Next.js SSR output (`.next`) is **not static files** — nginx/R2 static serving can't host it.
3. The app needs **Postgres** (drizzle/pg); the pipeline provisions **MongoDB** only.

## Root Cause
Template/architecture mismatch: a Node/Next.js SSR workspaces monorepo (with a Node Fastify+Postgres API fronted by a FastAPI supervisor) was deployed using the FARM (FastAPI + static React + MongoDB) template. The immediate build error (`Command "build" not found`) is just the first point where that mismatch surfaces.

## Fixes
- **Code / E1 (owner):** This app is not deployable on the FARM template as-is. Either (a) target a Node/Next.js-capable deployment path and provision Postgres for the Fastify API, or (b) restructure the project to match a supported FARM app (a flat `frontend/` with a real static `build` script and a single FastAPI `backend/` on MongoDB — dropping the Node Next.js/Fastify/Postgres stack). A simple manifest patch cannot bridge this.
- **User decision:** Confirm the intended production architecture / correct template for a Next.js + Node-API + Postgres app before re-deploying.

## Manifest state note
A `config.yaml` override (env_paths = backend/.env only) plus the full farm manifest set is now staged in GCS for this deployment. It correctly fixes the pull_source issue, but the build cannot succeed until the architecture/template mismatch above is resolved.
