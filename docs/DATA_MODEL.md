# Personal OS — Canonical Data Model

Stage 3 deliverable. This document is the single source of truth for every entity the
Personal Operating System stores, how entities relate, how integrity is enforced, how data is
indexed, and how the schema evolves without major migrations.

Companion documents:

- `docs/INFORMATION_ARCHITECTURE.md` — where each entity appears in navigation and which route owns it.
- Code mirror: `packages/core/src/types/*` (entity definitions), `packages/core/src/store/state.ts`
  (collections), `packages/core/src/schema/relations.ts` (integrity rules),
  `packages/core/src/schema/indexes.ts` (index catalog + completion history).

Scope note: this stage defines the **model** only. No feature/backend behavior is added; new
collections are registered and empty until their owning stage wires them up.

---

## 1. Foundations

### 1.1 ID scheme

- Every entity ID is an opaque UUIDv4 generated by `newId()` (`crypto.randomUUID()` with a
  deterministic fallback). IDs never encode type, workspace, or time.
- The **collection** is the type namespace. A reference is `(collection, id)`; type is never
  inferred from the string.
- Natural keys exist only where content is inherently unique and human-meaningful (§4.4):
  `Tag.name`, `User.handle`, `Achievement.key`, `Integration.provider + kind`.
  Natural keys are validated, never used as foreign keys.

### 1.2 Canonical entity base

Every entity inherits this trait set (`packages/core/src/types/base.ts`, `CanonicalEntity`):

| Trait | Fields | Rule |
|---|---|---|
| Identity | `id`, `type` | `type` is a stable string discriminator matching the collection's entity kind. |
| Ownership | `ownerId → User`, `workspaceId → Workspace`, `scope` | `scope ∈ private \| workspace \| team \| link`. |
| Timestamps | `createdAt`, `updatedAt` | Millisecond epoch (`Timestamp = number`). `updatedAt` is stamped by the store on every write; `createdAt` is immutable. |
| Lifecycle | `deletedAt`, `archivedAt`, plus per-entity `status` | Soft delete (`deletedAt`) is permanent-mark, not removal. Archive is recoverable shelving. `status` carries domain state (§1.3). Precedence when reading: `deletedAt` → hidden; else `archivedAt`/`status: archived` → shelved; else `status`. |
| Optimistic concurrency | `version` | Incremented on every write; a sync engine must reject writes against a stale `version`. |
| Audit | `audit: { createdBy, updatedBy, origin, templateId }` | `origin ∈ manual \| capture \| ai \| import \| system \| integration`. `templateId` records which Template spawned the entity (null otherwise). |
| Permissions | `scope` + role matrix (§1.4) | Stored per entity; enforcement is centralized, not per-field. |
| Sync | `sync: { revision, syncedAt, pending, conflict }` | `pending` = has unpushed changes; `conflict ∈ none \| local \| remote` (§1.5). |

**v1 adoption status.** The eleven v1 collections (`tasks`, `events`, `notes`, `projects`,
`goals`, `habits`, `habitCheckins`, `timeBlocks`, `reminders`, `attachments`, `aiObjects`) predate
the base and store no ownership/audit/sync columns yet. For them, ownership is implicit
(single local profile) and readers must treat **missing** ownership as `private`/local. The base
fields are adopted additively (nullable → defaulted) when sync ships; no migration is required
(§7). Every entity defined in this stage ships with the full base from day one.

### 1.3 Status model

Each entity declares its own status union; there is no shared mega-enum (shared enums force
coordinated migrations when any member changes). Rules:

- `active` (or domain synonyms such as `open`, `ready`, `connected`) is the default at creation.
- `archived` appears only where shelving is meaningful; entities without it use `archivedAt`.
- Terminal states (`done`, `completed`, `redeemed`, `reversed`, `dismissed`) are set explicitly and
  are never auto-reverted except through documented transitions.
- Enum evolution: add members freely; never rename or remove; readers must treat unknown members
  as their nearest non-terminal bucket (§7.2).

### 1.4 Permission model

`scope` per entity + role per membership:

| Role | Read | Create | Edit | Delete | Share |
|---|---|---|---|---|---|
| Owner (`ownerId`, role `owner`) | yes | yes | yes | yes | yes |
| Admin | yes | yes | yes | yes (non-owner content: no) | yes |
| Member | yes (scope ≥ workspace) | yes | own entities | own entities | no |
| Guest | entities explicitly scoped `link` | no | no | no | no |
| System AI | read across scope via `refs` only | writes `AI*` entities only | no | never | no |

Per-entity permissions are stated in the catalog. The AI row is architectural: AI never receives
ambient authority — it reads only what an explicit `refs`/`contextRefs` list points at (§4.5).

### 1.5 Sync model

Local-first: the on-device state is authoritative until a sync engine says otherwise. Sync classes:

| Class | Semantics | Entities |
|---|---|---|
| Live | bidirectional; conflicts resolved by `version` (last-writer-wins at field-set granularity) | Task, Note, Event, TimeBlock, Goal, Project, Milestone, Habit, Routine, LifeArea, Notebook, Page, Meeting, JournalEntry, LifeMemory |
| Append-only | never rewritten; merges are unions; corrections are new rows | HabitCheckIn, XPTransaction, AIMessage (once `complete`), Attachment metadata, FocusSession (after end) |
| Device-local | deliberately not synced; `syncedAt` stays null | Notification read/dismiss state, running timer of FocusSession |
| Server-authoritative | server wins any conflict | User, Integration, built-in Achievement/Template definitions |
| Derived | never synced; rebuilt from source rows | CompletionHistory, all indexes, `Tag.usageCount`, `Goal.progress` cache |

### 1.6 Storage layout

`AppState` = 42 normalized collections, each `Record<ID, Entity>` (`store/state.ts`), plus
`profile` (the local user's projection of `User`) and `settings`. Collections are flat and
denormalized on purpose: point lookups are O(1), joins happen in memory through indexes (§6), and
adding a collection is a free, migration-free operation (§7.3).

## 2. The multi-belonging task (critical requirement)

**One Task record. Many memberships. Never copies.**

A Task belongs to work structure, time structure, personal structure, and people simultaneously —
each dimension is a **nullable foreign key on the single task row**, never a duplicated record:

| # | Dimension | Field on Task | Target | Cardinality | Notes |
|---|---|---|---|---|---|
| 1 | Workspace | `workspaceId` | `workspaces` | N:1, nullable (legacy = local) | Ownership dimension. |
| 2 | Project | `projectId` | `projects` | N:1, nullable | v1 field. |
| 3 | Goal | `goalIds[]` | `goals` | N:M, ordered | v1 field; a task may advance several goals. |
| 4 | Milestone | `milestoneId` | `milestones` | N:1, nullable | Stage-3 field; completes Goal → Project → Milestone → Task. |
| 5 | Habit | `habitId` | `habits` | N:1, nullable | v1 field; the generated/linked instance of a behavior. |
| 6 | Routine | `routineId` | `routines` | N:1, nullable | Step of a routine sequence. |
| 7 | Calendar | `calendarId` | `calendars` | N:1, nullable | Which calendar the task's dates render on. |
| 8 | Time block | *(inverse)* `timeBlocks.taskId` | `tasks` | 1:N | Blocks point at the task; the task stores nothing (no edge duplication). |
| 9 | Life area | `lifeAreaId` | `lifeAreas` | N:1, nullable | Health / Work / Family … |
| 10 | Person | `assigneeId` | `members` | N:1, nullable | The person = `Member` (see catalog). Local self-assignment uses the owner's own member row. |
| 11 | Subtask tree | `parentTaskId` | `tasks` | N:1, nullable | Subtask is a **pattern**, not an entity (§3.7). |
| 12 | Tag | `tags[]` | `tags` (by name) | N:M natural key | §4.4 — auto-vivified, never dangling. |
| 13 | Category | `categoryId` | `categories` | N:1, nullable | Exactly one category; many tags. |
| 14 | Reminders | *(inverse)* `reminders.taskId` | `tasks` | 1:N | Authoritative direction is child→parent. `task.reminderIds[]` is deprecated and always empty (§7.6). |

Anti-duplication rules:

1. **Never** create a second Task row to express membership. "A task in three goals" is one row
   with three `goalIds`.
2. **Never** store the same edge on both sides. Where both fields historically exist
   (`task.reminderIds` + `reminder.taskId`), exactly one is canonical (child→parent) and the other
   is deprecated.
3. Lenses are queries, not records: Today, Calendar, Planner, Inbox are filtered views over the
   same task rows (`docs/INFORMATION_ARCHITECTURE.md` §route map). Opening a task from any lens
   reaches the same record.
4. A task created from a Habit, Routine step, Meeting action item, or AI suggestion keeps its
   single identity; the origin stays a reference or an `audit.origin` marker, never a clone.

## 3. Entity catalog

Conventions used by every block: **ID** = UUID unless a natural key is listed; **created/updated**
= `createdAt`/`updatedAt` from the canonical base; **deleted/archived** = lifecycle rule; **audit /
permissions / sync** = base traits unless overridden. "v1" marks entities that still await base
trait adoption (§1.2). Entities are grouped; collection names are exact.

### 3.1 Identity & tenancy

#### User — collection `users`
- **ID**: UUID; natural key `handle` (unique, lowercase). Email unique when present.
- **Ownership**: self-owned; `workspaceId` is the home workspace.
- **Relationships**: 1:N `members` (Member.userId); 1:1 `profile` projection (local `profile`);
  referenced by `audit.createdBy`/`updatedBy` everywhere.
- **Required**: `handle`, `displayName`.
- **Optional**: `email`, `avatarUrl`, `timezone`, `locale`, `lastSeenAt`.
- **Status**: `active | invited | suspended | deleted`.
- **Created/updated**: base. **Deleted/archived**: soft (`deletedAt`); suspension uses `status`.
- **Audit**: base (`origin: system` for provisioned users). **Permissions**: self-edit only;
  admins may suspend. **Sync**: server-authoritative — identity resolves before everything else.

#### Workspace — collection `workspaces`
- **ID**: UUID. Tenancy root for every other entity (`workspaceId`).
- **Ownership**: `ownerId → User`.
- **Relationships**: parent of all collections (§1.2); 1:N `teams`, `members`, `calendars`,
  `integrations`. Deleting a workspace is a tenant teardown = cascade of every contained entity.
- **Required**: `name`.
- **Optional**: `plan`, `color`, `icon`, `settings{}` (feature flags, defaults).
- **Status**: `active | archived`.
- **Created/updated**: base. **Deleted/archived**: soft delete; archive hides but keeps data.
- **Audit**: base. **Permissions**: owner full; admin edit; member read. **Sync**: server-authoritative.

#### Team — collection `teams`
- **ID**: UUID.
- **Ownership**: `ownerId → User`, `workspaceId → Workspace`.
- **Relationships**: N:1 workspace; 1:N `members` (Member.teamId), 1:N `shifts`.
- **Required**: `name`.
- **Optional**: `description`, `color`, `icon`.
- **Status**: `active | archived`.
- **Created/updated**: base. **Deleted/archived**: soft; members detach (nullify), shifts cascade.
- **Audit**: base. **Permissions**: workspace-scoped; admin+ manages. **Sync**: live.

#### Member — collection `members` — **the canonical "person"**
- **ID**: UUID. Unique on `(workspaceId, userId)`.
- **Ownership**: `ownerId → User` (self), `workspaceId → Workspace`.
- **Relationships**: N:1 user, N:1 workspace, N:1 team (optional); target of
  `task.assigneeId`, `actionItem.assigneeId`, `shift.memberId`, `approval.requesterId/approverId`.
- **Required**: `userId` (an invitation first creates a pending `User`, then this row), `role`
  (`owner | admin | member | guest`).
- **Optional**: `teamId`, `displayName` (override), `avatarUrl`, `joinedAt`.
- **Status**: `active | invited | suspended | left`.
- **Created/updated**: base. **Deleted/archived**: soft; `left` is the terminal role state.
- **Audit**: base (role changes logged via `updatedBy`). **Permissions**: admin+ grants roles;
  owner role cannot be removed. **Sync**: live.

#### Shift — collection `shifts`
- **ID**: UUID.
- **Ownership**: `ownerId → User`, `workspaceId → Workspace`.
- **Relationships**: N:1 member (required), N:1 team (optional); may project an `Event`
  (soft link, not stored both ways).
- **Required**: `memberId`, `startsAt`, `endsAt`.
- **Optional**: `title`, `location`, `notes`, `breakMin`, `teamId`.
- **Status**: `scheduled | active | completed | cancelled | swapped`.
- **Created/updated**: base. **Deleted/archived**: cascade when the member leaves; otherwise soft.
- **Audit**: base (`origin` records manual vs integration-created). **Permissions**: member reads
  own shifts; admin+ edits. **Sync**: live.

#### Approval — collection `approvals`
- **ID**: UUID.
- **Ownership**: `ownerId → User`, `workspaceId → Workspace`.
- **Relationships**: polymorphic child of any entity via `(entityType, entityId)`; decision emits
  a `Notification`.
- **Required**: `requesterId`, `entityType`, `entityId`, `status`.
- **Optional**: `approverId`, `decidedAt`, `comment`, `dueAt`.
- **Status**: `pending | approved | rejected | cancelled | expired`.
- **Created/updated**: base. **Deleted/archived**: soft; pending approvals expire via `status`.
- **Audit**: base — `origin` + the decision trail (`requesterId`, `approverId`, `decidedAt`).
  **Permissions**: requester creates; approver decides; others read. **Sync**: live.

### 3.2 Planning & structure

#### LifeArea — collection `lifeAreas`
- **ID**: UUID.
- **Ownership**: `ownerId`, `workspaceId`.
- **Relationships**: 1:N tasks (`task.lifeAreaId`), 1:N routines (`routine.lifeAreaId`),
  1:N goals via `goal.lifeAreaId`.
- **Required**: `name`.
- **Optional**: `description`, `color`, `icon`, `order`.
- **Status**: `active | archived`.
- **Created/updated**: base. **Deleted/archived**: soft; refs nullify (§4.3).
- **Audit**: base. **Permissions**: workspace scope. **Sync**: live.

#### Goal — collection `goals` (v1)
- **ID**: UUID.
- **Ownership**: implicit today (v1); adopts `ownerId`/`workspaceId` additively.
- **Relationships**: 1:N projects (`project.goalIds[]`); 1:N habits (`habit.goalId`);
  1:N notes (`note.goalIds[]`); 1:N tasks (`task.goalIds[]`); N:1 life area (`goal.lifeAreaId`).
- **Required**: `title`, `horizon`, `status`, `progress`.
- **Optional**: `description`, `targetAt`, `metric{label,current,target,unit}`, `lifeAreaId`.
- **Status**: `draft | active | completed | archived`.
- **Created/updated**: base. **Deleted/archived**: refs nullify in projects, habits, notes, tasks.
- **Audit**: base adoption pending. **Permissions**: workspace scope. **Sync**: live;
  `progress` is a derived cache (recomputable from milestones/tasks).

#### Project — collection `projects` (v1)
- **ID**: UUID; unique name per workspace (enforced by `PersonalOS.addProject`).
- **Ownership**: implicit today (v1).
- **Relationships**: N:M goals (`project.goalIds[]`); 1:N milestones (`milestone.projectId`);
  1:N tasks (`task.projectId`); 1:N notes, 1:N events; container role for its milestones.
- **Required**: `name`, `status`, `order`.
- **Optional**: `summary`, `color`, `goalIds[]`.
- **Status**: `active | paused | completed | archived`.
- **Created/updated**: base. **Deleted/archived**: nullify task/note/event refs; **cascade**
  milestones (their only meaning is project-scoped).
- **Audit**: base adoption pending. **Permissions**: workspace scope. **Sync**: live.

#### Milestone — collection `milestones`
- **ID**: UUID.
- **Ownership**: `ownerId`, `workspaceId`.
- **Relationships**: N:1 project (required); 1:N tasks (`task.milestoneId`).
- **Required**: `projectId`, `title`.
- **Optional**: `summary`, `dueAt`, `order`, `completedAt`.
- **Status**: `open | completed | dropped | archived`.
- **Created/updated**: base. **Deleted/archived**: cascade on project delete;
  on own delete tasks nullify. **Audit**: base. **Permissions**: follows project.
  **Sync**: live; `completedAt` derived from task progress is allowed to drift (cache).

#### Task — collection `tasks` (v1, extended in Stage 3)
- **ID**: UUID.
- **Ownership**: implicit today (v1); gains nullable `workspaceId` (§2 dimension 1).
- **Relationships**: the hub — see §2 for the full 14-dimension membership table. Out:
  project, goals, milestone, habit, routine, calendar, life area, assignee (person), parent task,
  tags, category; inverse: subtasks, time blocks, events, reminders, attachments, habit check-ins.
- **Required**: `title`, `status`, `priority`, `order`, `source`.
- **Optional**: `notes`, `dueAt`, `scheduledAt`, `startedAt`, `completedAt`, `estimateMin`,
  `projectId`, `goalIds[]`, `milestoneId`, `parentTaskId`, `habitId`, `routineId`, `calendarId`,
  `lifeAreaId`, `categoryId`, `assigneeId`, `workspaceId`, `tags[]`, `reminderIds[]` (deprecated),
  `recurrence{freq,interval}`.
- **Status**: `inbox | open | in_progress | done | cancelled | archived`.
- **Created/updated**: base; `updatedAt` stamped by store. **Deleted/archived**: hard-remove API
  (`deleteTask`) cascades subtasks and attachments/reminders, nullifies time blocks, events,
  check-ins (§4.3); soft delete replaces it when sync ships.
- **Audit**: base adoption pending; `source ∈ manual | capture | ai | habit | import` is the
  v1 origin marker. **Permissions**: workspace scope; assignee may edit. **Sync**: live.

#### Subtask — *pattern, not an entity*
- A subtask **is** a `Task` with `parentTaskId` set. No separate collection, no copies.
- Depth is unbounded in the model; UI caps rendering depth. Deletion cascades (parent → children).
- Progress = derived (`selectSubtaskProgress`), never stored on the parent.

#### Habit — collection `habits` (v1)
- **ID**: UUID.
- **Ownership**: implicit today (v1).
- **Relationships**: N:1 goal (`goalId`); 1:N check-ins (`habitCheckins.habitId`);
  1:N generated/linked tasks (`task.habitId`); N:1 reminder (via `reminder.habitId`).
- **Required**: `title`, `cadence`, `daysOfWeek`, `targetPerPeriod`, `period`.
- **Optional**: `color`, `icon`, `goalId`, `lifeAreaId` (adoption pending).
- **Status**: lifecycle `archived: boolean` (v1) → canonical `archivedAt` on adoption.
- **Created/updated**: base. **Deleted/archived**: cascade check-ins; nullify task and reminder refs.
- **Audit**: base adoption pending. **Permissions**: workspace scope. **Sync**: live definitions;
  check-ins are append-only.

#### Routine — collection `routines`
- **ID**: UUID.
- **Ownership**: `ownerId`, `workspaceId`.
- **Relationships**: 1:N tasks (`task.routineId` — steps realized as tasks);
  N:1 life area; `TimeBlockKind "routine"` covers its scheduled instances.
- **Required**: `title`.
- **Optional**: `description`, `lifeAreaId`, `steps[{title, taskId, durationMin}]`,
  `cadence`, `daysOfWeek`.
- **Status**: `active | archived`.
- **Created/updated**: base. **Deleted/archived**: nullify task refs; step `taskId`s nullify.
- **Audit**: base. **Permissions**: workspace scope. **Sync**: live.

### 3.3 Time

#### Calendar — collection `calendars`
- **ID**: UUID.
- **Ownership**: `ownerId`, `workspaceId`.
- **Relationships**: 1:N events (`event.calendarId`); 1:N tasks (`task.calendarId`);
  N:1 integration (provider calendars are owned by an `Integration`, soft link via
  `providerCalendarId` + `Integration.mappings`).
- **Required**: `name`.
- **Optional**: `color`, `provider` (`local | google | outlook | apple`),
  `providerCalendarId`, `syncEnabled`, `isDefault`, `timezone`.
- **Status**: `active | hidden | archived`.
- **Created/updated**: base. **Deleted/archived**: nullify event/task refs; soft delete.
- **Audit**: base. **Permissions**: workspace scope; provider calendars read-only while linked.
  **Sync**: live locally; provider mirror direction = server-authoritative when integration is on.

#### Event — collection `events` (v1, extended)
- **ID**: UUID.
- **Ownership**: implicit today (v1); gains nullable `calendarId`.
- **Relationships**: N:1 calendar (`calendarId`, Stage 3); N:1 project; 1:1 optional task
  (`event.taskId`); may be referenced by a meeting (`meeting.eventId`).
- **Required**: `title`, `startsAt`, `endsAt`, `allDay`, `source`.
- **Optional**: `notes`, `location`, `projectId`, `taskId`, `calendarId`.
- **Status**: implicit (upcoming/overdue are queries, not states).
- **Created/updated**: base. **Deleted/archived**: nullify task/project/calendar refs.
- **Audit**: base adoption pending. **Permissions**: workspace scope. **Sync**: live.

#### TimeBlock — collection `timeBlocks` (v1)
- **ID**: UUID.
- **Ownership**: implicit today (v1).
- **Relationships**: N:1 task (`taskId` — the canonical Task → TimeBlock edge);
  N:1 event (`eventId`); `kind` may mirror a routine.
- **Required**: `title`, `startsAt`, `endsAt`, `kind`.
- **Optional**: `taskId`, `eventId`, `completedAt`.
- **Status**: implicit; `completedAt` marks execution.
- **Created/updated**: base. **Deleted/archived**: hard-remove (no UI path yet);
  task delete nullifies `taskId`.
- **Audit**: base adoption pending. **Permissions**: workspace scope. **Sync**: live.

#### Reminder — collection `reminders` (v1)
- **ID**: UUID.
- **Ownership**: implicit today (v1).
- **Relationships**: N:1 task (`taskId`, canonical edge), N:1 event, N:1 habit;
  emits a `Notification` when fired (`firedAt`).
- **Required**: `fireAt`, `method`.
- **Optional**: `message`, `taskId`, `eventId`, `habitId`, `firedAt`.
- **Status**: implicit (`firedAt` non-null = fired; missed = past `fireAt`).
- **Created/updated**: base. **Deleted/archived**: cascade with task/event/habit targets
  (a reminder cannot outlive the thing it reminds about).
- **Audit**: base adoption pending. **Permissions**: follows target. **Sync**: live payload;
  firing state is device-local until the sync engine exists.

### 3.4 Knowledge & capture

#### Note — collection `notes` (v1)
- **ID**: UUID.
- **Ownership**: implicit today (v1).
- **Relationships**: N:1 project; N:M goals; 1:N attachments (`attachment.ownerType: "note"`);
  tag membership (natural key); linkable from Pages (soft).
- **Required**: `title`, `body`, `tags[]`, `source`.
- **Optional**: `projectId`, `goalIds[]`, `pinned`.
- **Status**: implicit (pin is a flag; archive lands with base adoption).
- **Created/updated**: base. **Deleted/archived**: cascade attachments.
- **Audit**: base adoption pending; `source` is the origin marker. **Permissions**: workspace
  scope. **Sync**: live.

#### Notebook — collection `notebooks`
- **ID**: UUID.
- **Ownership**: `ownerId`, `workspaceId`.
- **Relationships**: 1:N pages (`page.notebookId`, cascade on delete).
- **Required**: `title`.
- **Optional**: `description`, `color`, `icon`, `order`.
- **Status**: `active | archived`.
- **Created/updated**: base. **Deleted/archived**: cascade pages; soft.
- **Audit**: base. **Permissions**: workspace scope. **Sync**: live.

#### Page — collection `pages`
- **ID**: UUID.
- **Ownership**: `ownerId`, `workspaceId`.
- **Relationships**: N:1 notebook (required); 1:N attachments (owner = page);
  may link Notes (soft `noteIds` in body markdown, no stored edge).
- **Required**: `notebookId`, `title`.
- **Optional**: `body` (markdown), `icon`, `order`.
- **Status**: `draft | active | archived`.
- **Created/updated**: base. **Deleted/archived**: attachments cascade; soft delete.
- **Audit**: base. **Permissions**: follows notebook. **Sync**: live.

#### Attachment — collection `attachments` (v1)
- **ID**: UUID.
- **Ownership**: implicit today (v1); by extension the owner entity's.
- **Relationships**: polymorphic child of any entity via `(ownerType, ownerId)` — canonically
  `Note → Attachment`, also tasks, pages, journal entries, documents. Soft may-source link:
  `document.attachmentId`.
- **Required**: `ownerType`, `ownerId`, `name`, `mimeType`, `sizeBytes`, `source`.
- **Optional**: `url`.
- **Status**: implicit (upload state lives with the host UI).
- **Created/updated**: base. **Deleted/archived**: cascade with owner (active for tasks/notes).
- **Audit**: base adoption pending. **Permissions**: never exceed the owner's.
  **Sync**: append-only metadata; blob bytes follow the storage integration.

#### Document — collection `documents`
- **ID**: UUID.
- **Ownership**: `ownerId`, `workspaceId`.
- **Relationships**: may originate from an Attachment (`attachmentId`, nullable);
  searchable corpus for AI (`refs` target documents); may spawn a Recording/Transcript
  (soft, via those entities' own links).
- **Required**: `title`, `mimeType`, `sizeBytes`, `source` (`upload | import | generated`).
- **Optional**: `url`, `storageKey`, `attachmentId`, `text` (extraction result), `tags[]`.
- **Status**: `processing | ready | failed | archived`.
- **Created/updated**: base. **Deleted/archived**: soft; extraction text is re-derivable.
- **Audit**: base. **Permissions**: follows owner/scope; text extraction inherits them.
  **Sync**: metadata live; `text` is derived (server re-extractable).

#### Recording — collection `recordings`
- **ID**: UUID.
- **Ownership**: `ownerId`, `workspaceId`.
- **Relationships**: N:1 meeting (optional); 1:1 transcript (stored on `transcript.recordingId`);
  may source a Document.
- **Required**: `title`, `startedAt`.
- **Optional**: `endsAt`, `durationMs`, `mimeType`, `url`, `meetingId`, `documentId`.
- **Status**: `recording | ready | failed | archived`.
- **Created/updated**: base. **Deleted/archived**: transcript nullifies; soft.
- **Audit**: base. **Permissions**: follows meeting/scope. **Sync**: metadata live;
  bytes via storage integration; row is append-only after `ready`.

#### Transcript — collection `transcripts`
- **ID**: UUID.
- **Ownership**: `ownerId`, `workspaceId`.
- **Relationships**: N:1 meeting (required edge `meetingId` — canonically Meeting → Transcript),
  N:1 recording (when voice-sourced); 1:N action items (`actionItem.transcriptId`).
- **Required**: `title`, `source` (`meeting | recording | upload`).
- **Optional**: `meetingId`, `recordingId`, `language`, `fullText`,
  `segments[{speaker, startMs, endMs, text}]`, `confidence`.
- **Status**: `processing | ready | failed | archived`.
- **Created/updated**: base. **Deleted/archived**: action items nullify (they survive as
  converted tasks); soft.
- **Audit**: base. **Permissions**: follows meeting. **Sync**: append-only once `ready`
  (segments are never rewritten).

#### Meeting — collection `meetings`
- **ID**: UUID.
- **Ownership**: `ownerId`, `workspaceId`.
- **Relationships**: 0..1 transcript (inverse edge on `transcript.meetingId`);
  1:N action items (via transcript, plus direct `actionItem.meetingId`);
  0..1 calendar event (`eventId`); N:1 project; N:M attendees (`attendeeIds → members`).
- **Required**: `title`, `startsAt`.
- **Optional**: `endsAt`, `notes`, `location`, `attendeeIds[]`, `eventId`, `projectId`.
- **Status**: `scheduled | completed | cancelled | archived`.
- **Created/updated**: base. **Deleted/archived**: transcript + action items nullify links;
  event ref nullifies; soft.
- **Audit**: base. **Permissions**: attendees read; owner/organizer edits.
  **Sync**: live.

#### ActionItem — collection `actionItems`
- **ID**: UUID.
- **Ownership**: `ownerId`, `workspaceId`.
- **Relationships**: N:1 transcript (`transcriptId`), N:1 meeting (`meetingId`), N:1 assignee;
  **→ Task**: conversion creates exactly one Task and stores the link on `actionItem.taskId`
  (single source of truth for the edge; the task carries `source: "ai"`/`import`, never a copy of
  the transcript context).
- **Required**: `title`.
- **Optional**: `transcriptId`, `meetingId`, `taskId`, `assigneeId`, `dueAt`, `order`.
- **Status**: `open | converted | dismissed | done`.
- **Created/updated**: base. **Deleted/archived**: nullifies `taskId` (the created task survives).
- **Audit**: base (`origin: ai` for machine-extracted items). **Permissions**: follows meeting.
  **Sync**: live; `converted` is terminal for the link (`taskId` stays).

#### JournalEntry — collection `journalEntries`
- **ID**: UUID; natural uniqueness on `entryDate` per owner (one entry per day, merge on conflict).
- **Ownership**: `ownerId`, `workspaceId`.
- **Relationships**: 1:N attachments (owner = journal entry); tag membership; completion of
  tasks/habits on the same day feeds its prompts (query, no stored edge).
- **Required**: `entryDate` (day anchor), `body`.
- **Optional**: `title`, `mood`, `energy` (1–5), `tags[]`.
- **Status**: `draft | complete | archived`.
- **Created/updated**: base. **Deleted/archived**: attachments cascade; soft.
- **Audit**: base. **Permissions**: `private` scope by default (journal is the most sensitive
  surface). **Sync**: live.

### 3.5 Memory, progress & rewards

#### LifeMemory — collection `lifeMemories`
- **ID**: UUID.
- **Ownership**: `ownerId`, `workspaceId`; AI writes within the owner's authority only.
- **Relationships**: **→ CompletionHistory** (derivation edge: pattern/observation memories are
  materialized by reading the completion projection — §3.6); `sourceRefs[]` points at the concrete
  entities behind the memory (tasks, goals, habits …). Referenced by `AIInsight.refs`.
- **Required**: `kind` (`observation | preference | pattern | milestone | relationship`), `text`.
- **Optional**: `title`, `confidence` (0–1), `sourceRefs[]`, `reinforcedAt`, `decayedAt`.
- **Status**: `active | stale | forgotten`.
- **Created/updated**: base. **Deleted/archived**: soft; `forgotten` is decay, not removal.
- **Audit**: base with `origin: ai` (system-generated) or `manual` (user-pinned).
  **Permissions**: private scope; AI may create, user may always edit/delete.
  **Sync**: live; derived-from-history memories are marked `derived: true` in `payload` and are
  rebuildable.

#### CompletionHistory — *derived projection, not a collection*
- **ID**: none — records are `(entityType, entityId, at)` tuples.
- **Definition**: `buildCompletionHistory(state)` in `schema/indexes.ts` unions three source
  streams: `task.completedAt`, `habitCheckins.checkedAt`, `focusSessions` (ended, status
  `completed`), ordered by `at`.
- **Relationships**: feeds LifeMemory (`kind: pattern`), Achievement thresholds, XP back-fill,
  Insights. Stored nowhere → never stale, never migrated, rebuilt on demand.
- **Deletion**: disappears automatically when its source row goes. **Permissions**: inherits the
  owner's. **Sync**: derived — never synced.

#### Achievement — collection `achievements`
- **ID**: UUID; natural key `key` (stable code, shipped by the system, immutable).
- **Ownership**: `ownerId`, `workspaceId` (the per-user instance); definitions are
  system-owned (`origin: system`).
- **Relationships**: threshold evaluated over CompletionHistory; unlock emits an
  `XPTransaction(reason: achievement)` and a `Notification`.
- **Required**: `key`, `title`.
- **Optional**: `description`, `icon`, `category`, `threshold`, `xpAward`, `progress`, `unlockedAt`.
- **Status**: `locked | unlocked | hidden`.
- **Created/updated**: base. **Deleted/archived**: never deleted (hidden at most); soft delete
  reserved for retired definitions.
- **Audit**: base (`origin: system`). **Permissions**: system writes; user reads.
  **Sync**: server-authoritative definitions; `unlockedAt`/`progress` are append-only progress.

#### XPTransaction — collection `xpTransactions`
- **ID**: UUID. Append-only ledger — corrections are compensating negative rows, never edits.
- **Ownership**: `ownerId`, `workspaceId`.
- **Relationships**: polymorphic source `(entityType, entityId)` for what earned/spent it;
  reward redemption references this ledger; progress feeds Achievement thresholds.
- **Required**: `amount` (integer; negative = spend), `reason`
  (`task_complete | habit_streak | goal_milestone | achievement | focus_session | reward_redeem |
  manual | correction`).
- **Optional**: `entityType`, `entityId`, `note`, `balanceAfter`.
- **Status**: `posted | reversed` (reversal = new compensating row).
- **Created/updated**: base. **Deleted/archived**: rows are never deleted or edited.
- **Audit**: base with strict `origin`. **Permissions**: system + `manual` (owner) only.
  **Sync**: append-only — merges are unions, conflicts impossible by construction.

#### Reward — collection `rewards`
- **ID**: UUID.
- **Ownership**: `ownerId`, `workspaceId`.
- **Relationships**: redemption spends `XPTransaction(reason: reward_redeem)`.
- **Required**: `title`, `cost` (XP ≥ 0).
- **Optional**: `description`, `icon`, `availableAt`, `redeemedAt`.
- **Status**: `available | locked | redeemed | archived`.
- **Created/updated**: base. **Deleted/archived**: soft; redeemed rows are kept for the ledger.
- **Audit**: base. **Permissions**: owner creates/spends (or template/system).
  **Sync**: live; redemption is a two-write transaction (reward + ledger row) committed together.

#### FocusSession — collection `focusSessions`
- **ID**: UUID.
- **Ownership**: `ownerId`, `workspaceId`.
- **Relationships**: N:1 task (optional), N:1 time block (optional); completion feeds
  CompletionHistory and may earn XP.
- **Required**: `startedAt`.
- **Optional**: `endsAt`, `plannedMin`, `taskId`, `timeBlockId`, `interruptions`, `mode`
  (`flow | pomodoro | custom`).
- **Status**: `running | paused | completed | aborted`.
- **Created/updated**: base. **Deleted/archived**: soft only (completed sessions are history).
- **Audit**: base. **Permissions**: private/workspace. **Sync**: device-local while
  `running` (timer state), append-only once ended.

### 3.6 Taxonomy & reuse

#### Tag — collection `tags`
- **ID**: UUID; **natural key `name`** (trimmed, lowercased, unique) — membership edges on
  tasks/notes store the name, not this id (§4.4).
- **Ownership**: `ownerId`, `workspaceId`.
- **Relationships**: N:M tasks and notes via `tags[]` (auto-vivified rows).
- **Required**: `name`.
- **Optional**: `color`, `usageCount` (derived cache), `status`.
- **Status**: `active | archived`.
- **Created/updated**: base. **Deleted/archived**: archived tags keep rendering past membership;
  rows are never hard-deleted while referenced.
- **Audit**: base. **Permissions**: workspace scope. **Sync**: live; `usageCount` is derived.

#### Category — collection `categories`
- **ID**: UUID.
- **Ownership**: `ownerId`, `workspaceId`.
- **Relationships**: self-tree (`parentId` — parent/children); N:1 tasks
  (`task.categoryId`, exactly one per task); `entityTypes[]` declares where the category may apply.
- **Required**: `name`.
- **Optional**: `parentId`, `description`, `color`, `entityTypes[]`.
- **Status**: `active | archived`.
- **Created/updated**: base. **Deleted/archived**: re-parent children to the deleted node's
  parent (nullify parent edge); task refs nullify.
- **Audit**: base. **Permissions**: workspace scope. **Sync**: live.

#### Template — collection `templates`
- **ID**: UUID; unique on `(name, target)` per workspace; built-ins ship with `builtin: true`.
- **Ownership**: `ownerId`, `workspaceId`; built-ins are system-owned.
- **Relationships**: spawns entities of `target` type; the spawned row records the link in
  `audit.templateId` (one-way — instances never reference back).
- **Required**: `name`, `target` (`task | note | goal | habit | project | routine | meeting |
  journal_entry`).
- **Optional**: `title`, `body`, `payload{}` (a `New*Input` snapshot), `tags[]`, `icon`, `order`,
  `builtin`.
- **Status**: `active | archived`.
- **Created/updated**: base. **Deleted/archived**: instances are untouched (soft delete only).
- **Audit**: base (`origin: system` for built-ins). **Permissions**: system ships; owner edits
  custom. **Sync**: built-ins server-authoritative; custom live.

### 3.7 System

#### Notification — collection `notifications`
- **ID**: UUID.
- **Ownership**: `ownerId`, `workspaceId`; per-user inbox row.
- **Relationships**: emitted by Reminders, Achievements, streaks, Approvals, AI insights;
  polymorphic source `(entityType, entityId)`.
- **Required**: `title`, `kind` (`reminder | achievement | streak | ai_insight | approval |

- **Optional**: `body`, `entityType`, `entityId`, `fireAt`, `priority`, `readAt`, `dismissedAt`.
- **Status**: `pending | delivered | read | dismissed`.
- **Created/updated**: base. **Deleted/archived**: dismissed rows purge on a retention window;
  soft delete in-model.
- **Audit**: base (`origin` = emitting subsystem). **Permissions**: private inbox.
  **Sync**: payload live; `readAt`/`dismissedAt` device-local until the sync engine exists.

#### Integration — collection `integrations`
- **ID**: UUID; unique on `(provider, kind)` per workspace.
- **Ownership**: `ownerId`, `workspaceId`; connection is user-scoped.
- **Relationships**: owns provider-side Calendar/Document mirrors through `mappings{}` (entityId ↔
  external id); `lastSyncAt` bounds trust in mirrored rows.
- **Required**: `provider`, `kind` (`calendar | tasks | notes | health | communication |

- **Optional**: `accountLabel`, `scopes[]`, `settings{}`, `mappings{}`, `lastSyncAt`, `lastError`.
- **Status**: `connected | paused | error | disconnected`.
- **Created/updated**: base. **Deleted/archived**: disconnect (`disconnected`) keeps `mappings`

- **Audit**: base (every sync mutation records `origin: integration`). **Permissions**: admin+

  side; the row stores no secrets).

### 3.8 AI

**AI → existing user data** (architectural rule): every AI surface references data it may read
through explicit ref lists — `AIObject.refs`, `AIConversation.contextRefs`, `AIMessage.refs`,
`AIInsight.refs`, each `{ entityType, entityId }`. AI never copies authoritative content into its
own rows; prompt snapshots are ephemeral and stored only as `prompt`/`payload` hints. When a
target entity is deleted, its refs become **soft**-stale: reported by integrity tooling, pruned on
next write, never block deletes (§4.5).

#### AIObject — collection `aiObjects` (v1)
- **ID**: UUID. Actionable AI output (suggestion, plan, summary, draft, answer).
- **Ownership**: implicit today (v1).
- **Relationships**: `refs[]` → existing entities (polymorphic, soft).
- **Required**: `kind`, `title`, `status`.
- **Optional**: `body`, `payload{}`, `refs[]`, `model`, `prompt`.
- **Status**: `pending | accepted | dismissed`.
- **Created/updated**: base. **Deleted/archived**: hard-remove on dismiss/purge (v1).
- **Audit**: base adoption pending (`model`/`prompt` are the audit trail).
  **Permissions**: same scope as its refs. **Sync**: live while pending; terminal rows are
  history.

#### AIConversation — collection `aiConversations`
- **ID**: UUID.
- **Ownership**: `ownerId`, `workspaceId`.
- **Relationships**: 1:N messages (`message.conversationId`, cascade);
  `contextRefs[]` → existing user data (soft).
- **Required**: `title`, `status`.
- **Optional**: `summary`, `model`, `pinnedAt`, `lastMessageAt`, `contextRefs[]`.
- **Status**: `active | archived`.
- **Created/updated**: base. **Deleted/archived**: cascade messages; soft.
- **Audit**: base (`origin: ai` metadata + model name). **Permissions**: private scope;
  context refs grant read-through only. **Sync**: live; context refs re-resolve per device.

#### AIMessage — collection `aiMessages`
- **ID**: UUID.
- **Ownership**: inherits conversation's owner/workspace.
- **Relationships**: N:1 conversation (required, cascade); `refs[]` → data cited in the answer.
- **Required**: `conversationId`, `role` (`user | assistant | system`), `content`.
- **Optional**: `model`, `tokens`, `refs[]`.
- **Status**: `complete | streaming | error`.
- **Created/updated**: base; immutable after `complete`. **Deleted/archived**: cascade with
  conversation only.
- **Audit**: base (`model`, `tokens`). **Permissions**: inherits conversation.
  **Sync**: append-only once complete.

#### AIInsight — collection `aiInsights`
- **ID**: UUID.
- **Ownership**: `ownerId`, `workspaceId`; system-generated within owner scope.
- **Relationships**: `refs[]` → the user data behind the insight (soft); surfaced in Insights,
  notifications, and LifeMemory candidates.
- **Required**: `kind` (`trend | risk | suggestion | summary`), `title`, `body`.
- **Optional**: `refs[]`, `confidence`, `severity` (`info | warning | action`), `dedupeKey`
  (unique per owner — re-detections reinforce instead of duplicating), `readAt`.
- **Status**: `pending | read | acted | dismissed`.
- **Created/updated**: base. **Deleted/archived**: dismissed rows purge on retention; soft.
- **Audit**: base (`origin: ai`, model, `confidence`). **Permissions**: read-through of refs

### 4.1 Required chains

```
Goal ──(project.goalIds[])──▶ Project ──(milestone.projectId)──▶ Milestone
                                                          │
                            Task ──(task.milestoneId)─────┘
Task ──(task.parentTaskId)──▶ Task (subtask)
Task ──(timeBlock.taskId)──▶ TimeBlock        Task ──(task.calendarId)──▶ Calendar ──▶ Event
Task ──(reminder.taskId)──▶ Reminder          Task ──(habitId / routineId)──▶ Habit / Routine
Task ──(lifeAreaId / workspaceId / assigneeId / projectId / goalIds / categoryId / tags)──▶ …

Note ──(attachment.ownerType/ownerId)──▶ Attachment
Meeting ──(transcript.meetingId)──▶ Transcript ──(actionItem.transcriptId)──▶ ActionItem
ActionItem ──(actionItem.taskId)──▶ Task          (conversion: ONE task, linked, never cloned)
```

### 4.3 Delete semantics

- **cascade** — the child's reason to exist dies with the parent (subtasks, check-ins, reminders,
  milestones under a project, pages under a notebook, messages under a conversation).
- **nullify** — the child survives, minus the link (tasks keep existing after their project goes;
  an action item stays open after its transcript is deleted).
- **block** — reserved for referential anchors: deleting a `Workspace` is a tenant teardown
  (cascade everything) rather than a blocked operation; no `block` edges are active today.
- Cascade code lives next to the delete API (`PersonalOS.deleteTask/deleteProject/deleteGoal/
  deleteHabit/deleteNote`). The edge table is the contract those implementations must satisfy;
  `schema/relations.ts` verifies actual state against it.

### 4.4 Natural-key joins (tags & categories)

- Task/Note → Tag membership stores the tag **name** (lowercase). Integrity is by convention:
  writing a tag name **auto-vivifies** the `Tag` row (create-if-missing), so membership can never
  dangle. Archived tags keep rendering; they just don't accept new joins.
- Categories are hard-id (`task.categoryId`) because they are structural and tree-shaped;
  tags are soft-name because they are social and free-form.
- `findDanglingRefs` therefore never inspects `tags[]` — by design, not by omission.

### 4.5 Referential integrity

- **Hard refs** — concrete-id edges in §4.2. A hard ref must resolve to a live row in the target
  collection or be `null`. Validation: `findDanglingRefs(state)` → `[{collection, id, field,
  target, targetId}]`. Runs: in tests (CI), on import (`PersonalOS.importData`), and as a dev-mode
  hydrate assertion; a sync engine must run it before pushing.
- **Soft refs** — AI `refs`, `sourceRefs`, `contextRefs`. Stale soft refs are *expected* (data
  evolves); they are surfaced to integrity tooling and pruned the next time the holding entity is
  written. They never block a delete.
- **Polymorphic refs** — validated by dispatching `ownerType`/`entityType` through
  `ENTITY_COLLECTION` (the same map drives attachment cleanup in `deleteTask`/`deleteNote`).
- **Repair policy** — tooling may nullify stale soft refs and re-parent orphaned categories;
  it must never fabricate rows. Hard-ref violations found in production are treated as bugs in
  the delete path, not routine corruption.

## 5. Indexing

### 5.1 Principles

1. The normalized maps **are** the primary index: `Record<ID, Entity>` gives O(1) point lookup for
   every id, on every collection.
2. Secondary indexes are **derived, in-memory, and rebuilt** — never persisted, never synced
   (§1.5 "derived"). Rebuild is a single linear pass; at the 10⁵–10⁶ row scale a local machine
   rebuilds in milliseconds, which buys migration freedom: indexes can change shape any release.
3. Multi-membership indexes **repeat the row reference**, not the row: one task in three goals
   appears as three `(goalId → taskRef)` entries over the same record (§2 anti-duplication #1).
4. Selectors (`engines/task-engine.ts`) consume indexes opportunistically; correctness never
   depends on an index being present.

### 5.2 Index catalog (mirror of `schema/indexes.ts`)

| Index | Key | Serves |
|---|---|---|
| `tasks.byStatus` | `TaskStatus` | Today, Inbox, counts, sidebar dots |
| `tasks.byProject` | `projectId` | `/projects/:id`, `selectProjectTasks` |
| `tasks.byGoal` | each of `goalIds[]` | goal detail / progress rollup |
| `tasks.byMilestone` | `milestoneId` | milestone drill-down |
| `tasks.byParent` | `parentTaskId` | subtask trees, `selectTaskChildren` |
| `tasks.byHabit` | `habitId` | habit → instance tasks |
| `tasks.byRoutine` | `routineId` | routine step checks |
| `tasks.byLifeArea` | `lifeAreaId` | area rollups |
| `tasks.byCalendar` | `calendarId` | calendar visibility filters |
| `tasks.byAssignee` | `assigneeId` | team "assigned to me" views |
| `tasks.byCategory` | `categoryId` | category browser |
| `tasks.byTag` | each of `tags[]` | tag pages, `/tasks?tag=` |
| `tasks.byWorkspace` | `workspaceId ?? "_unscoped"` | tenant scoping; `_unscoped` = legacy local rows |
| `tasks.byDueDay` | `startOfDay(dueAt \| scheduledAt)` | agenda, Today, overdue |
| `eventsByDay` | `startOfDay(startsAt)` | `/calendar` |
| `completionHistory` | `at` (ordered tuples) | LifeMemory, Achievements, Insights |

Rules: nullable keys are **skipped** (a null FK is the absence of an edge, not a key);
multi-valued fields index every member; keys are strings (day keys are midnight timestamps).

### 5.3 Scaling notes

- Point lookups + grouped scans cover every route in `docs/INFORMATION_ARCHITECTURE.md` with no
  nested loops; worst-case scans are per-collection and linear in that collection only.
- If a collection outgrows in-memory rebuild (≥10⁶ rows), the migration path is: persist the
  serialized index beside the data and rebuild lazily on schema-key change — indices are derived,
  so this is an optimization, not a schema change.
- Never index ephemeral UI state (filters, selections) in the data layer.

## 6. Evolution without major migrations

The schema grows by **addition**. Concretely:

1. **Additive fields only.** Fields are added with a default (`null`, `""`, `[]`, or a factory
   default). Existing rows deserialize without transformation because readers use the default when
   the field is absent — legacy rows are exercised by tests (`schema/schema.test.ts` builds indexes
   over pre-Stage-3 shaped tasks).
2. **No renames, no removals, no type changes.** To retire a field: (a) stop writing it,
   (b) keep reading it with a default for one release, (c) document it as deprecated in this file.
   Precedent: `task.reminderIds[]` — canonical edge moved to `reminder.taskId`; the field remains,
   always empty, harmless (§7.6 of the implementation notes).
3. **Enum members are append-only.** Renaming or removing a status member is a breaking change;
   readers bucket unknown members into their nearest non-terminal equivalent (§1.3).
4. **New collections are free.** `store/state.ts` registers the collection; `normalizeState()`
   fills any collection missing from an old persisted payload with `{}`. This is why
   `SCHEMA_VERSION` stays at `1` across Stage 3's 31 new collections — versioned migrations are
   reserved for *shape* changes (field semantics, renames), and `MIGRATIONS[n]` runs only then.
   Old data loads, new collections arrive empty, zero migration code.
5. **Per-entity `meta` escape hatch.** Experimental attributes land in a nullable `payload{}`
   / `settings{}` bag (already: `AIObject.payload`, `Workspace.settings`,
   `Integration.settings/mappings`) instead of schema churn; promoted fields graduate to typed
   fields additively.
6. **Derived data never migrates.** CompletionHistory, indexes, `usageCount`, `progress` are
   rebuilt from source rows, so they can change shape at will without touching persisted bytes.
7. **Soft delete over hard delete.** Adoption of `deletedAt`/`archivedAt` on v1 collections is an
   additive column, not a rewrite; retention/purge jobs handle eventual hard deletes.
8. **Backups and exports** (`PersonalOS.exportData`) carry the raw envelope; import runs through
   the same `normalizeState` path, so exports from older versions import into newer ones for free.
